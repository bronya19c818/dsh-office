# 块标识全覆盖、变更集回退与事件驱动的改动感知

## Problem Statement

AI 改 Word 文档时按"段落编号 + 段首文字"定位。用户的每一次手改、AI 自己的每一次插入，都会让编号整体漂移，于是出现两种结果：要么整批操作停在中途、要重新读一遍全文，要么模型自己算偏移、算错就改错位置。已经落地的书签块标识只覆盖了一部分操作：`set_text`、`insert_paragraphs`、`insert_footnote`、`format_text`、`delete_range` 的起点、`format_table`、`set_image` 认块 id，`replace_text` 仍是全文查找替换，`delete_range` 的终点仍只吃段号。

Excel 和 PowerPoint 里的 AI 修改没有任何退路。Excel 的外部修改不进撤销栈，还会清空已有记录；PowerPoint 同样。AI 一次清洗几百行、改几十个形状，出错只能重来。

"用户改了什么"目前靠每次读取时遍历全文比对快照。WPS 的 COM 侧已经能订阅 `DocumentChange` 事件（ApplicationEvents4，IID `00020A01-0000-0000-c000-000000000046`，DispId 3，实测 `Advise` 成功、回调到达），但还没有接进 helper，所以每次感知用户改动都要付一次全文遍历的代价。

## Solution

把块标识做成段落的一等坐标，覆盖全部以段落为锚的 Word 操作；为每一批修改建立可校验、可回退的变更集，Word、Excel、PowerPoint 都适用；把文档变更事件接进 helper，让"用户刚改过"变成一个廉价的脏标记，而不是每次都扫全文。

用户在 WPS 或 Word 里照常编辑，AI 定位用块 id，编号漂移不再影响写入；用户说"撤回上一次"时，插件能把那一批改动按原样退回去，退之前先确认文档没被其他人改过，避免把用户后来的手改一起冲掉。

## User Stories

1. 作为一个在 WPS 里改稿的用户，我希望 AI 在我上方插入段落后仍能改到我说过的那一段，而不是改错位置，这样我不用每次都重述"是第几段"。
2. 作为一个同时编辑的用户，我希望 AI 认的是段落本身，不是我打字时不断变化的序号，这样我们可以在同一份文档上并行工作。
3. 作为一个让 AI 做局部替换的用户，我希望查找替换能限定在我点名的那一段里，而不是全篇找，这样别的章节里的同一句话不会被误改。
4. 作为一个让 AI 删除一段内容的用户，我希望删除范围的两端都能用块 id 指定，这样删错段的事故不会因为编号漂移而发生。
5. 作为一个让 AI 批量改文字的用户，我希望某一段改完之后它的块 id 不变，这样同一批里后续的操作还能继续指向它。
6. 作为一个让 AI 在 Excel 里清洗数据的用户，我希望改错了能退回上一批，而不是重新上传或手动恢复。
7. 作为一个让 AI 在 PowerPoint 里改版式的用户，我希望被改的文字、形状、页面能按批回退，这样试错成本降下来。
8. 作为一个让 AI 改 Word 的用户，我希望回退前插件先确认这一批之后没人再动过文档，这样回退不会连带冲掉我后来的手改。
9. 作为一个用户，我希望文档在我改过之后被 AI 发现时，只告诉我改了哪几段、旧文与新文各是什么，而不是让我重新读整篇。
10. 作为一个用户，我希望 AI 自己的改动不会被误报成"用户改动"，这样变更摘要里只出现我自己动过的地方。
11. 作为一个用户，我希望"用户改过"这类信息来自文档事件，而不是每次读取都重新扫一遍全文，这样长文档的响应更快。
12. 作为一个用户，我希望事件只告诉我"文档变了"，具体改了哪里由读取时比对得出，这样不会因为事件缺少细节而丢掉定位。
13. 作为一个用户，我希望回退有一条明确的边界：只退 AI 的那一批，不退我自己的操作。
14. 作为一个用户，我希望回退失败时给出原因和可选项，而不是悄悄只退了一半。
15. 作为一个在 Word 和 WPS 之间切换的用户，我希望两边的块 id、回退、变更摘要行为一致。
16. 作为一个用旧调用方式（只给段号）的用户，我希望现有工具不因为新增块 id 而改变语义，这样已有脚本和习惯不受影响。
17. 作为一个用户，我希望块 id 在文档里尽可能不打扰我：默认不显示，我打开"显示书签"时才看得到。
18. 作为一个交付文档的用户，我希望交付前的书签清理由 doc-converter 负责，插件这边不重复实现。
19. 作为一个长文档用户，我希望即使有上千个段落，读取时给块 id 也不会明显变慢。
20. 作为一个让 AI 分批改长文的用户，我希望每一批都有可识别的批次号，这样我可以指定"退回第几批"。
21. 作为一个用户，我希望回退后文档仍然能正常保存、导出，不留下半截的中间状态。
22. 作为一个开发者，我希望这些能力通过 helper 的 JSON 命令协议暴露，这样验收脚本可以只在一个接缝上测真实应用。

## Implementation Decisions

**块标识的语义**

块 id 是段落的位置锚，不带内容含义。名字形如 `_dsh_<8位哈希>`，哈希只在创建时用于避免重名；段落内容变化不改名，段落被删除则 id 失效。位置匹配优先于名字：同一位置已有书签时复用它的名字，读到的永远是"当前这一段"的 id。

书签锚在段落末尾的零宽位置，而不是整段范围。这样在段前插入新段不会把书签拉过去，实测中修掉了"新段继承旧 id"的漂移。

写操作清空段落文本时会连带删掉书签，所以 `set_text` 之后按原 id 重建；`insert_paragraphs` 在段前插入后不重建（锚点是零宽，本就不受影响）。

**操作覆盖**

`replace_text` 增加可选的段落限定：给了块 id 或段号时只在该段范围内查找；不给时保持现在的全文替换语义。默认行为不变，旧调用不受影响。

`delete_range` 的 `to` 接受块 id。`para` 与 `to` 同为 id 时按两个书签的范围取区间；混用 id 与段号时报参数错误，避免语义含糊。

工具层文档里明确写出：Word 的段落类操作 `para` 可以是段号，也可以是 `blocks:true` 读到的 id（`_dsh_...` 或 `#_dsh_...`）。

**变更集**

每一批 `office_edit` 生成一条变更记录：批次号、时间、文档标识、每个操作执行前的状态、以及对应的逆操作。逆操作按应用分派：Excel 记录被覆盖范围的值与格式、插入/删除的行列、新建的表与图表；PowerPoint 记录被改形状的旧文本与属性、新增或删除的页面；Word 记录段落旧文本与旧格式，并以整批撤销步作为兜底。

回退命令按批次号或"最近 N 批"执行。执行前先比对当前文档指纹与该批次结束时的指纹；不一致就拒绝，并报告"这一批之后文档被改过"，让用户选择另存副本再回退。

Word 优先走原生撤销栈（一批一个撤销步），失败时用记录的逆操作；Excel 与 PowerPoint 只能走逆操作。

变更记录首版只存在 helper 进程内存里，随进程退出丢弃。跨会话持久化不在本 spec 范围。

**事件**

helper 在附着到已运行的 Word/WPS 实例时，订阅 `ApplicationEvents4` 的 `DocumentChange`（DispId 3）。回调只置脏标记并记时间戳，不碰 COM 对象；下一次命令读取时消费该标记，决定是否需要比对快照。连接点在 `quit` 或进程退出时释放。

事件缺失（旧版本、受保护文档、订阅失败）时退回纯快照比对，行为不降级。

**工具层**

`office_read` 的 `blocks` 与 `changes` 已实现；本次新增 `office_revert`（按批次号回退），并在 `office_status` 里显示"文档自上次读取后是否被改过"。

错误码新增三类：块不存在、批次已过期（文档被改过）、回退冲突（逆操作无法应用）。

## Testing Decisions

好测试只看外部行为：文档的文本与结构、工具回复里的字段，不测内部类与私有方法。

唯一接缝是 helper 的 JSON 命令协议：编译 helper、起进程、按行发命令、按行读回复。`scripts/office-smoke.mjs` 已经是这个形态，新增用例沿用同一套驱动，不引入新的测试入口。

要覆盖的矩阵：

- 块 id 稳定性：上方插入、上方删除、段落移动、`set_text` 改写、段前插入之后，原段落的 id 不变，写入命中正确段落。
- 局部替换：限定段落后，其他段落里的同一文本不被改动。
- 删除范围：两端用 id 时删对区间；混用 id 与段号时报参数错误。
- 回退：Word、Excel、PowerPoint 各一批，改后回退，断言文档回到批次前的文本与结构。
- 回退保护：批次之后用户再改一处，回退被拒绝并给出原因。
- 事件：订阅后修改文档，脏标记置位；下一次读取消费后清零；事件不可用时退回快照比对仍能得到正确 diff。
- 兼容：只给段号的旧调用结果不变。

WPS 12 与微软 Word 各跑一遍，脚本只操作它自己在临时目录创建的文档。

## Out of Scope

- 隐藏书签的清理与交付前移除，交 doc-converter 默认开启的附加功能。
- Excel 单元格级、PowerPoint 形状级的块标识（本 spec 只做 Word 段落）。
- 多人实时协同、OT 冲突合并。
- 变更集的跨会话持久化与审计日志。
- PowerPoint 版式与动画的逐项还原；回退只保证文本、形状、页面这几类。
- 书签在文档另存、共享、复制场景下的生命周期管理。

## Further Notes

书签数量会随段落数增长，读取时的书签索引是一次遍历；上千段落的成本需要实测，超过阈值时改成增量维护。

WPS 的 `Bookmarks.Add` 只有两参数签名，没有隐藏标志；书签默认不显示，用户主动打开"显示书签"才会看到 `_dsh_` 名字。

事件回调运行在 COM 线程，任何在回调里调用文档对象的尝试都可能造成重入，这条约束必须写进实现注释。

`replace_text` 的默认全文语义被很多现有用法依赖，段落限定只能是可选参数，不能改变默认。
